# 0.4.6 PDF 백지 미리보기 대응

2026-09-30. 사용자가 0.4.5 및 도우미 연결을 확인했으나 현재 답변/전체 대화/선택 영역의 Chrome 인쇄 미리보기가 모두 백지라고 보고했다.

## 수정

- 인쇄 전용 문서를 별도의 로컬 about:blank iframe에 DOM API로 구성하고 해당 프레임의 print()를 호출한다. 원본 페이지에는 인쇄 CSS나 aice-printing 클래스를 넣지 않는다.
- 원본 사이트의 html/body 인쇄 숨김 스타일이 인쇄 문서에 전파되지 않도록 분리한다. 서버 전송이나 새 권한은 추가하지 않는다.
- afterprint 직후 인쇄 문서를 삭제하지 않는다. 미리보기의 지연 참조를 위해 한 개만 유지하고 다음 PDF 출력에서 교체한다. 탭 이동/종료 때도 사라진다. 오류 시에는 즉시 정리한다.
- 수식의 위치·clip·overflow·flex 속성과 읽을 수 있는 @font-face를 함께 보존한다. 선택 영역도 수식 계산 스타일을 보존한다. 교차 출처로 읽을 수 없는 폰트 CSS는 브라우저 보안 정책에 따라 복사하지 않는다.
- 인쇄가 끝나거나 실패했을 때 확장 팝업 버튼이 계속 잠긴 채 남지 않도록 해제한다.

## 검증과 한계

|검사|결과|
|---|---|
|기존 npm test + 수명주기 검사|통과|
|동일 호스트 숨김 CSS에서 0.4.5/수정본 비교|0.4.5 유효 opacity=0, 수정본 opacity=1 및 visibility=visible|
|Chrome/Edge headless 네이티브 프레임 print 호출|72건 통과|
|동일 조건 HWPX 추출|72건 통과, 각 수식 2개 및 생략 0개|
|PDF 6개|한글·본문·제목·코드 텍스트 및 색상 검사 통과, 대표 PDF 시각 확인|

브라우저 조건: 밝음/다크/흐림/호스트 인쇄 숨김 × DPR/zoom 1/1.25/2 × 현재/전체/선택 × Chrome/Edge. Page.printToPDF는 하위 프레임을 대상으로 하지 못하므로, PDF 산출물은 실제 유지된 인쇄 문서의 DOM을 별도 테스트 페이지에서 출력했다. 프레임의 네이티브 print 호출은 따로 실행했다. 이를 실제 사용자 Chrome 미리보기 UI 검증으로 간주하지 않는다.

사용자 탭 접근은 타임아웃 및 `Debugger unattached`로 실패했다. 따라서 사용자의 정확한 CSS/인쇄 이벤트 원인은 확정하지 못했다. 사이트 스타일 충돌과 조기 제거 경로를 제거했으며, 사용자 환경 재확인은 필요하다. Windows 도우미는 변경하지 않았다.

## 재시험

현재 불러온 `dist/chrome-load-0.4.5` 폴더의 내용만 0.4.6으로 갱신했다. 경로를 유지하여 수동 확장 ID가 바뀌지 않게 한다.

1. 열린 인쇄 창을 취소한다.
2. chrome://extensions 에서 해당 확장의 새로고침 버튼을 누르고 0.4.6을 확인한다.
3. ChatGPT 대화 페이지도 새로고침한다.
4. 현재 답변 PDF부터 확인하고 전체 대화/선택 영역을 검사한다.

도우미 재설치와 새 폴더 로드는 필요 없다. 스토어 업로드/공개 범위 변경은 수행하지 않았다.

프레임 인쇄 방식 참고: [MDN Printing](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing).
